# Appointment Companion V3.01 UI refinement

## Scope

V3.01 is a focused refinement of the existing V3 Appointment Companion. It is not a rebuild.

The V3 state, calculations, rules, summary/share contracts, Cloud behaviour, migration logic, Meal Deal preview and specialist-tool contracts remain authoritative unless a small state/UI compatibility change is explicitly required below.

## Agreed appointment flow

### Customer essentials first

Customer-level facts sit close to the customer name and use one consistent vertical visual language:

- Home status: Homeowner / Tenant
- Referred by an existing customer
- National League referral

Home status remains mutually exclusive rather than an on/off switch. Referral and National League retain their existing mutual-exclusion behaviour.

Selecting Tenant hides and deselects Boiler Cover.

### Compact service selection

Replace the large 2x2 service cards with compact service rows:

- ⚡🔥 Energy
- 🛜 Broadband
- 📱 Mobile
- 🛠️ Boiler Cover

Selecting a service expands that service's detail section further down the same appointment page. Service sections are not separate pages and do not have service-level back buttons.

### Progress dots

Each selected service row displays grouped completion dots:

- Current
- UW
- Exit fee only when exit fees apply

Examples:

- ⚡🔥 Energy ● ○
- ⚡🔥 Energy ● ●
- ⚡🔥 Energy ● ● ○ when exit fees apply

For Mobile, Current and UW dots aggregate all included SIMs. The Exit fee dot appears if at least one included SIM has exit fees enabled and is complete only when every enabled SIM exit fee is populated.

The overall appointment percentage continues to count the underlying required comparison items, including each included SIM.

### Exit fees

Exit fees are conditional, not a mandatory zero-value field.

Default for new appointments: Exit fees do not apply.

When the toggle is off:
- there is no exit-fee input;
- there is no exit-fee progress dot;
- exit fee is not part of the completeness denominator;
- stored fee values do not affect calculations.

When the toggle is on:
- the fee input appears;
- the exit-fee requirement/dot appears;
- a positive fee value is required before that requirement is complete.

Energy uses one "Exit fees apply?" toggle. For dual fuel, electricity and gas fee boxes appear. At least one positive fee is sufficient, so zero does not have to be typed for the other fuel.

Legacy compatibility: if a saved V3 record already contains a positive exit fee and has no explicit exit-fee toggle state, normalisation turns the relevant toggle on.

### Required comparison figures

Current and UW costs remain mandatory for every selected service/SIM. Blank or zero Current/UW comparison figures do not unlock the summary.

### Visual direction

Use the calmer UW-inspired service palette already proven in 2.42:
- Energy: blue/teal family
- Broadband: green family
- Mobile: pink family
- Boiler Cover: warm orange family
- Generic shell: UW purple/dark-purple with a softer neutral canvas

Replace abstract service symbols with meaningful emoji. Appointment may use 📋.

## Out of scope

Do not redesign:
- calculations/business rules beyond conditional exit-fee inclusion;
- Meal Deal logic;
- summary/share payload contracts;
- Cloud sync/reconciliation;
- legacy migration except the exit-fee compatibility inference;
- EV Companion;
- Should I Fix;
- PET;
- tariff source-of-truth integration.

## Safety

All V3.01 work is made on branch `v3.01-ui-refinement`. Existing 2.42 and the published `/PWA/v3/` route remain untouched until a later explicit publish decision.
